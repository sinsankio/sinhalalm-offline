# Tokenizer Parity: Parity Gate 3

The browser can only reproduce the model's behavior if it turns text into exactly the token IDs the model was trained on. For SinhalaLLM-1.7B, this is not guaranteed, since its pre-tokenizer relies on the Unicode classes `\p{L}` and `\p{M}` and on the zero-width characters, which the JavaScript implementation in transformers.js must reproduce exactly. An early check on 210 inputs found no difference ([sinhalallm-inspection.md](sinhalallm-inspection.md), S4), and gate 3 repeats it at scale.

In this document, we report parity gate 3, which compares the Python `tokenizers` library used by `transformers` 5.19.0 with the tokenizer of transformers.js 4.3.1.

### 1. Test set

The gate uses three groups of inputs:

- **Corpus** — 10,000 Sinhala sentences sampled with a fixed seed from four public sources at pinned revisions. Sentences are split on `.`, `?`, `!` and line breaks, deduplicated, kept between 5 and 300 characters and required to contain at least one Sinhala character.
- **Named edge cases** — 17 hand-written inputs that target known differences between Python and JavaScript and the Sinhala-specific parts of the pre-tokenizer.
- **Chat prompts** — the ten golden questions, wrapped in the model's ChatML template by each library.

| Source | Revision | Sentences | Candidates |
|---|---|---|---|
| `ChamaraVishwajithRajapaksha/sinhala-text-dataset` (first 200,000 rows) | `2a7cbe94` | 4,000 | 197,838 |
| `ChamaraVishwajithRajapaksha/sinhala-question-answer-pairs` (test split) | `bf34e2a7` | 3,000 | 12,012 |
| `ihalage/sinhala-finetune-qa-eli5` | `c47977fd` | 1,000 | 83,949 |
| `wikimedia/wikipedia` `20231101.si` (first 3,000 articles) | `b04c8d1c` | 2,000 | 118,657 |

Since the licenses of these sources differ, the sentences are regenerated by `make golden` and are not committed. Instead, `golden/tokenizer_manifest.json` records the full revisions, the seed and the SHA-256 hash of the generated corpus, and the test fails if the corpus on disk does not match that hash. The named edge cases are written for this project and are committed in `golden/tokenizer_cases.json`.

The edge cases cover text with and without the ZWJ, the zero-width non-joiner, a leading byte order mark, detached punctuation, a mix of tab, no-break space, U+2028, U+0085 and U+001C, repeated spaces, line breaks, English, digits, an emoji, HTML entities, mixed Tamil and Sinhala, vowel signs without a base consonant, a long conjunct word, ChatML special tokens and empty input.

### 2. Results

| Check | Result |
|---|---|
| Corpus sentences with identical token IDs | 10,000 of 10,000 |
| Named edge cases with identical token IDs | 17 of 17 |
| Chat prompts with identical text and token IDs | 10 of 10, after the template fix below |
| Corpus hash matches the manifest | yes |
| Regeneration from scratch matches the committed files | yes |

The transformers.js tokenizer reproduced the Python tokenizer on every input, including the inputs where Python and JavaScript disagree on what counts as whitespace. In other words, the Sinhala-aware pre-tokenizer survives the move to the browser unchanged, and the application can use the tokenizer from the published `tokenizer.json` without a custom port.

### 3. The chat template is not found by the browser tokenizer

The first run of the chat-prompt checks failed with "Cannot use apply_chat_template() because tokenizer.chat_template is not set". The model was saved with `transformers` 5.19.0, which stores the chat template in a separate `chat_template.jinja` file. In transformers.js 4.3.1, only processor classes read that file, while `AutoTokenizer` expects the template inside `tokenizer_config.json`.

This is the same kind of problem as the RoPE base in gate 1: a file layout written by a newer Python toolchain that the next tool in the chain does not read. The pipeline therefore writes a browser version of `tokenizer_config.json` with the template embedded, and the same function will package the tokenizer for the web application in Phase 3. With this change, all ten chat prompts matched the Python prompts, both as text and as token IDs.

### 4. Implications

- The browser uses the transformers.js tokenizer directly, and gate 3 runs on every `make ci`.
- The browser packaging of the model must include a `tokenizer_config.json` with the embedded chat template. Without it, the application would fail at the first question rather than silently, but the fix belongs in the pipeline rather than in the application code.
- Any later upgrade of transformers.js reruns gate 3 before it is merged.
